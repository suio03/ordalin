## What we tested

We wrote a small Express and SQLite API where users keep private notes and upload files: four source files, 81 lines. It contains three planted holes: SQL injection in the search, reading another user's note by id, and path traversal in a file download. Its README says it is a deliberately vulnerable test fixture.

We ran Claude Code once with the skill copied in from the repository at commit c1c8a8c and once with nothing installed. Both runs used the same model and settings and could read and write files, run commands and start subagents. The skill run was asked for a full security audit; the plain run was asked for a security audit with a report. Both were told not to run the app and not to ask questions. The test sessions also had a few of our own general skills loaded, the same for both runs.

## What we found

- **Both found everything we planted.** Each run reported the SQL injection, the note IDOR and the `/files` traversal, and both also found a second traversal in `/attachments` through an encoded slash and a request that crashes the server. We found no false alarms in either report.
- **The skill proved its findings.** For each candidate a fresh verifier wrote a small script that rebuilt the vulnerable line with dummy data and ran it in the macOS sandbox: the injection returned every user's token, and the fixed query returned nothing. The plain run said plainly that its proofs were derived, not executed.
- **It was strict about what counts.** The open upload-size problem stayed in needs_validation, because confirming it would mean installing and running the upload library. Hardening items such as headers and rate limits, which the plain run listed, are left out by design. It also noted that the `/attachments` read is blocked when any folder in the server's path starts with a dot.
- **It showed what it did not cover.** The report lists 13 coverage units, marks itself as a partial quick pass and names two areas a standard run should hunt next. It chose the quick profile on its own, even though we asked for a full audit, because the code was small.
- **It cost far more.** The skill run took 78 turns, 911 seconds and $8.41 at API prices, as reported by Claude Code. The plain run took 7 turns, 100 seconds and $0.35. Its output folder held 988 KB of notes, ledgers and scripts against one 204-line report.

This is one small API with one model, so read it as an example, not a benchmark.
